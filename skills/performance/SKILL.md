# 性能优化

## 铁律：先测量，后优化

1. **定义目标**：什么指标（延迟/吞吐/内存/CPU）？目标值多少？基线是多少？
2. **测量定位**：找到真实瓶颈——用计时/profiler（Node `--prof`、Python `cProfile`、Go pprof、浏览器 Performance）、日志耗时、数据库慢查询日志。**不要猜**。
3. **提出假设 + 优化**：针对瓶颈做最小改动。
4. **验证收益**：同样的测量方法对比前后；确认没有回归（`test_run`）。

## 常见瓶颈与对策

- **数据库**：缺索引（explain/执行计划）、N+1 查询、大结果集（分页）、锁等待
- **IO/网络**：串行请求改并发、重复请求合并、缓存（内存/本地）、压缩
- **CPU/算法**：热路径复杂度（O(n²)→O(n)）、重复计算（缓存结果）、对象分配
- **前端**：大包（代码分割）、渲染循环、布局抖动

## 工具配合

- `test_run` 跑基准/压测脚本；`semantic_search` 找热路径相关代码
- 用 `checkpoint_create` 保护优化前的状态；每步优化独立提交（便于回滚与对比）

## 交付

- 报告：基线 → 瓶颈位置 → 改动 → 收益（数字说话）
- 不要为了微优化牺牲可读性；复杂优化加注释说明为什么
