# 依赖管理

## 添加依赖

1. **先确认必要性**：这个功能能用手写/现有代码实现吗？引入新依赖的成本（体积/维护/供应链风险）值不值？
2. **选版本**：看是否已有锁文件版本；优先用稳定版；注意 peer 依赖与引擎要求。
3. **安装并锁版本**：用项目包管理器（npm/pnpm/pip/cargo/go）安装并更新锁文件；**确认锁文件被提交**。
4. **验证**：`test_run` 全绿；`git_diff` 确认只改了清单+锁文件+必要代码。

## 升级依赖

1. 先看变更范围：`npm outdated`（或对应工具）列出可升级项。
2. 分级：patch/minor 可批量；major 逐个评估（破坏性变更需读 changelog）。
3. **安全网**：升级前 `checkpoint_create`；升级后 `test_run`。
4. 升级安全相关依赖（涉及漏洞修复）优先。

## 清理与审计

- 删除未使用的依赖（配合 `code-review`/搜索确认无引用）。
- 定期 `security-audit` skill 检查已知漏洞。
- 版本冲突：`npm ls <pkg>` / `cargo tree` 定位重复版本，必要时对齐。

## 原则

- 少而精：依赖越少，攻击面与维护成本越低。
- 锁文件是版本真相：不要手动改锁文件，走包管理器。
- 大版本升级默认单独提交（`git_commit`），便于回滚与 review。
