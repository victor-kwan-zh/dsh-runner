# 安全审计

## 依赖层

1. **审计已知漏洞**：
   - npm 项目：`npm audit`（或 `pnpm audit`）；严重漏洞评估影响面与升级成本
   - Python：`pip-audit`；Rust：`cargo audit`；Go：`govulncheck`（无工具时用 `test_run` 或手动核对）
2. **依赖卫生**：检查 `package.json`/锁文件——多余依赖、过期版本、未用的传递依赖；权限过大的安装脚本。

## 代码层（结合 code-review 的维度）

- **注入**：拼接命令/SQL/路径/模板（`child_process` 用数组传参；SQL 用参数化；路径做校验）
- **密钥与敏感信息**：`git_diff`/`git_status` 排查 .env、密钥文件是否可能入库；config 里有没有硬编码口令
- **认证与授权**：暴露的接口/工具是否校验身份；本地服务是否只绑 127.0.0.1；token 是否明文落盘
- **不可信输入**：外部输入（网络/文件/用户）在边界处是否校验（大小、类型、白名单）
- **依赖供应链**：锁文件是否固定版本；新装依赖是否来自可信源

## 输出

- 按严重程度分级：严重（必须修，如远程执行/泄漏）/ 高 / 中 / 低
- 每条给：位置 + 风险 + 修复建议（具体到可执行）
- 结论：可上线 / 需修复后上线

## 注意

- 只审不改（除非用户要求修复）；大范围升级前先 `checkpoint_create`。
- 不要为了"看起来安全"而谎报；没把握的标注"待确认"。
